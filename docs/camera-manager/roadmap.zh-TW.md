## 原始三階段（2026-09-24 使用者拍板）

| 階段 | 內容 | 狀態 |
|---|---|---|
| 1. 停靠面板 | 面板、清單、就地編輯、雙向連動、人視高預設值、複製到其他樓層、匯出 Excel、③ 位置圖＋視野扇形、並排／還原、預覽視窗 | ✅ 完成（使用者實機回饋多輪，未完成最終驗收） |
| 2. Key Plan 與相機標記 | 一鍵 4 視圖（平面／剖面／等角）、B 型標記、表現法、室內／室外 | ✅ 大部分完成（提前併入第 1 階段）；每層總覽平面、A 型族群標記、拖標記連動相機 → 移到 Wave 2 |
| 3. 出圖與版本 | 一鍵排圖紙、相機視角版本、視覺精修 | ⏳ → Wave 3 |

## 收尾波次（2026-09-25 起）

### Wave 1｜MCP 測試工具　✅ 完成（2026-09-25）

讓 AI 能自動測試面板背後的同一套服務程式碼（D-023）。

| 工具 | 狀態 |
|---|---|
| `list_cameras` | ✅ |
| `run_camera_keyplan` | ✅ |
| `set_camera_pose` | ✅ |
| `copy_camera_to_level` | ✅ |
| `get_view_extents` | ✅ |

- ✅ 面板內「開啟並排」「編輯請求組裝」移到服務層共用。
- ✅ 規格書拆成四份文件。
- ⚠️ 工具本身尚未在 Revit 內實際呼叫過（見未驗證清單）。

### Wave 2｜Key Plan 完整版　⏳ 規劃中

1. **每層總覽平面** `Key Plan-總覽-<樓層名>`：該層所有相機的標記畫在同一張平面上。
2. **A 型相機標記（模型族群）**：一般模型族群（小相機體＋視線箭頭＋視野扇形，視野角與遠裁剪為參數），專屬子類別「相機標記」；透視圖本身以篩選器隱藏；需實測 Enscape 是否排除、數量表是否誤算。
3. **拖標記 → 相機跟著動**：在 Key Plan 平面／剖面上拖相機標記，相機位置／方向同步更新（目前只有「相機改了 → 標記重畫」單向）。

### Wave 3｜出圖與版本　⏳ 規劃中

1. **一鍵排圖紙**：每台相機一張圖紙（透視＋Key Plan 平面＋剖面＋等角），使用專案現有圖框，版面位置固定、之後可調。
2. **相機視角版本**：「儲存視角」並取名（例如「A 案」），可切回；存在 .rvt（Extensible Storage），同事開檔也能切換；內容＝眼睛位置、方向、上方向、視野、遠裁剪。
3. **視覺精修**：統一字體（Microsoft JhengHei UI 12–13 px）、8 px 間距、主要／次要按鈕區分；修正過時的 ToolTip 文字（例如「Key Plan 樣式」提示仍寫「模型半色調」，實際已改類別取代）。

### 之後｜MCP 自測　⏳

用 Wave 1 工具在測試模型（Snowdon Towers 等公開範例）上自動跑：

- 每台相機 `list_cameras` → `run_camera_keyplan` → `get_view_extents`，比對範圍是否符合 spec §10（室內房間 +0.6 m、室外扇形 +2 m、剖面包含平面剖切面…）。
- `set_camera_pose` 改高度／角度後重跑，確認標記與範圍跟著變。
- `copy_camera_to_level` 後確認新相機高度、方向相同、原相機不變。
- 兩種 `sectionMode`、兩種 `isoMode` 各跑一次，確認 `SectionModeUsed` 與 Section Box 上限。
- 手動移動剖面後重跑，確認 `SectionPreserved=true`；`resetSection=true` 後覆蓋。

### 最後｜使用者實測（只有人能判斷的項目）　⏳

- 面板手感：清單點擊編輯、樓層下拉、右鍵選單、地圖縮放／拖曳／點選的手勢是否衝突。
- 畫面判斷：Key Plan 的淡化程度、外輪廓清楚度、標記大小與透明度、樓層記號是否好讀。
- 並排視窗在「使用索引標籤檢視」開／關下的實際表現。
- 長時間使用是否再崩潰（開檔時面板開著／關著兩種情況）。
